# Shop Owner Phase 5 Capability Retirement Matrix

## Scope and decision rules

This is a freeze of the legacy owner ERP callers and data surfaces, not a new
authorization registry. It was characterized from the current route table,
`routes/shop-owner-erp.php`, `routes/shop-owner-erp-api.php`, and the caller
inventory. The authority for the seven approval rows is the Phase 4
[approval matrix](shop-owner-phase-4-approval-matrix.md). The generated
[ERP route matrix](shop-owner-erp-route-matrix.md) is a cross-check only;
where it differs from an executable owner route, this document records the
route and requires the capability test named below before retirement.

`OWNER_READABLE` means the owner may receive the listed shop-scoped record
set. `CONDITIONAL` means the route is only a page launcher or needs the
listed module/record capability; it is not a permission grant. `OWNER_DENIED`
means the owner must not receive the underlying staff/audit/sensitive data.
Module visibility never changes those classifications.

Abbreviations: `WS` = ERP workspace/module card and direct bookmarked URL;
`Shell` = canonical shell navigation; `AC` = Action Center; `Contract` =
`tests/Feature/BusinessScaling/OwnerErpPageContractTest.php`; `API` =
`tests/Feature/BusinessScaling/OwnerErpApiContractTest.php`; `Auth` =
`tests/Feature/BusinessScaling/OwnerErpAuthorizationTest.php`.

## Stop checkpoint

The seven approval redirect rows are supported by an authoritative OFF actor
and transition in the Phase 4 matrix. All other `STOP_FOCUSED_DESIGN` rows
have a caller/page route but no authoritative owner record/read or correction
boundary. They must not be exposed, redirected to an unrelated local page, or
treated as capability parity merely because the module is visible.
