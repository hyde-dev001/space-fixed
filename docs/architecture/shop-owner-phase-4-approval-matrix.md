# Shop Owner Phase 4 Approval Authority Matrix

This matrix is the Task 1 stop checkpoint for the seven binary Shop Owner approval policies. `OFF` means the owner decision stage is skipped; it does not approve, apply, disburse, settle, release, pay out, or terminally reject by itself. Each destination below reuses an existing domain state and an existing decision method or actor. No new fallback role, permission, status, approval table, or generic mutation endpoint is inferred here.

The source review used CodeGraph first, then the listed service, controller, model, route, notification, and focused-test evidence. All seven families meet the required evidence cells and are `PROVEN` for implementation. Any implementation must preserve the state guards and actor checks named in this table.

## Characterization evidence

The focused characterization test was necessary because Salary Adjustment had no existing approval test. It proves the existing non-proposer reviewer reaches `approved`, records the reviewer, leaves employee salary unchanged, and cannot self-approve a proposal. It also proves the existing Manager final repair-rejection method reaches terminal `rejected` only from `manager_reviewing` and records the Manager actor.

## Task 1 decision

All seven rows are `PROVEN`. Continue to Task 2. The matrix is evidence for implementation routing only; it does not authorize changing any domain service until the corresponding task adds failing tests, preserves these guards, and verifies the result.
