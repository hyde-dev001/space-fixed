# Shop module owner parity matrix

This matrix is the owner-administration companion to the [route inventory](shop-module-route-inventory.md). It was generated from the named `shop_owner.*` and `shop-owner.*` routes loaded by `bootstrap/app.php`. The owner guard is deliberately separate from employee self-service: an owner action operates on the selected shop/employee context, while `staff.*` personal attendance, leave, overtime, payslip, and shop-hours routes continue to require the authenticated employee.

## Contract

- Owners must be approved, non-suspended, tenant-scoped, and authenticated through `shop_owner`.
- Existing employee role/direct-permission middleware remains required for `user` routes; adding an owner guard never grants employee identity actions.
- Every owner row below has one module gate and an explicit owner controller/action path. Tests use the row's stable route-derived case name.
- Reference-only Inventory reads do not grant Retail or Repair mutation access. Retail product/POS mutations and Repair service/job mutations remain owned by their respective modules.
- Core settings/profile/notifications/dashboard routes are intentionally omitted from this module matrix and remain reachable when modules are disabled.

Current owner-route counts: CRM 13, Repair Operations 39, HR and Employees 15, Finance 20, Inventory 11, Retail Operations 40, Procurement 4, Logistics 3.

## Employee self-service exclusions

The following identity-sensitive families remain employee-only and are never made owner-accessible by a shared guard: `staff.attendance.*`, `staff.leave.*`, `staff.overtime.*`, `staff.payslips.my`, `staff.shop_hours.today`, and any personal document/check-in endpoint. Owner administration uses the dedicated rows in this matrix and must not impersonate an employee.
