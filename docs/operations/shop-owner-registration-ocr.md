# Shop Owner Registration OCR operations

Date: 2026-10-22. This guide describes the implemented browser-only screening and the evidence collected in the isolated development worktree. It does not authorize a deployment or production migration.

## What the score means

The applicant's browser runs local Tesseract.js over the selected required document image. The browser sends only a bounded evidence report; Laravel validates its shape and derives a categorical result attached to the immutable uploaded document version.

- **100% - Automated Checks Passed** means every applicable required automated check had sufficient matching evidence. It does not verify authenticity and never approves an application.
- **50% - Requires Further Review** means usable reading exists but evidence is partial or uncertain.
- **0% - Conflicting Evidence Detected** means reliable localized evidence conflicts with a required check. Plausible documents with field conflicts remain eligible for human review; an incompatible document family separately requires replacement in the applicant interface.
- **Not assessed**, **Unable to assess**, **Needs rescan**, and **Assessment incomplete** remain distinct states. Missing assets, OCR errors, or a score never replace the existing admission and review rules.

The existing authorized Super Admin workflow remains the only approval/rejection authority. Admins still inspect every required private document and supply the existing reviewer metadata. Browser evidence is applicant-controlled and preliminary.

## Applicant submission gate

Final submission waits while a newly selected required document is queued or scanning. A completed scan must establish a compatible document family or meaningful plausible government-document text/structure. Empty or junk OCR output and scans with no such evidence require a replacement; a reliably identified incompatible family also requires replacement. The submit handler checks this both on entry and immediately before dispatch after confirmation/CSRF retrieval.

The gate is separate from the score. A plausible business/owner/address/date conflict (including 0%) remains submitable for Super Admin investigation. Ambiguous or unfamiliar documents with positive government-document evidence remain submitable for manual review. A successfully scanned but unreadable image without such evidence requires a clearer retake. Genuine worker/asset/browser failures remain nonblocking. No pixel-layout or face classifier certifies document relevance, and browser results never establish authenticity.

The applicant sees the replacement message: **Invalid document image. We couldn't identify the required government document in your upload. Please upload a clear photo of the correct document.** No internal confidence threshold is shown.

This frontend correction requires deploying its matching rebuilt `public/build/`; it does not require a new migration or disabling hosting protections.

Use the pinned lockfiles and Node build tooling:

```powershell
pnpm install --frozen-lockfile
pnpm run build
node scripts/prepare-owner-ocr-assets.mjs --check
```

`pnpm run build` and `pnpm run dev` explicitly run `scripts/prepare-owner-ocr-assets.mjs`. The current bundle uses Tesseract.js/core 7.0.0 and English data 1.0.0. The generated `public/ocr/manifest.json` points to versioned same-origin worker, core, and language paths and records asset checksums. There is no runtime CDN fallback.

For the merge handoff, `public/ocr/` is generated from the locked packages and committed alongside `public/build/`. A Git-based Hostinger checkout therefore contains the worker, all compatible core variants, English model, licenses and checksum manifest without a build command on the web server. Future package upgrades must regenerate and commit both directories. A release/archive process must still include both complete directories under Laravel's public web root; do not deploy only the Vite manifest or omit binary/model files. `node scripts/prepare-owner-ocr-assets.mjs --check` verifies generated bytes against installed locked packages before packaging. Review the Git-tracked OCR inventory as well as the local directory.

The development verification created a temporary archive containing both directories and confirmed all 24 generated OCR files were included. ## Failure handling, privacy, and rollback

If the browser or a local asset is unavailable, the UI reports a technical failure and the applicant can continue after active scans settle. Unfinished or stale browser evidence is omitted at submit. A completed empty/junk reading instead requires replacement, independently of its administrative score. Malformed submitted metadata still fails Laravel validation. Raw OCR text, extracted values, ID/TIN information and word locations are never persisted in the report.

If the feature must be disabled, roll back the application/frontend release while retaining the nullable column and stored reports. Do not drop the column or erase report history as an automatic rollback. Existing private documents, viewed-document rules, registration status, decision audits, and customer verification are independent of the OCR report.
