## Resulting workflow map

- **Lost -> recovered before final approval:** reporting Rider submits details/condition/photo/confirmation -> original incident shows linked recovery -> Dispatcher authorizes eligible continuation and customer arrangement -> new Rider offer accepted -> real current movement/arrival/proof approval -> automatic completion. Stale final-loss approval cannot proceed.
- **Lost -> final loss:** Dispatcher acknowledgement -> reporting Rider Confirm Lost -> Dispatcher final approval -> terminal original loss plus eligible normal refund reservation. Staff/Finance/applicable Owner approvals, provider result and COD obligations remain with their existing services. Approval is not payout success.
- **Incident -> retry:** Dispatcher records resolved obstacle/customer arrangement and valid schedule -> existing source/batch-aware retry -> new offer acceptance -> any required actual custody transfer -> legitimate activation/arrival/proof/review -> verified delivery. Shop-held goods require receipt/inspection and authorized outbound handling; a checkbox cannot establish safety.
- **Incident -> shop return:** Dispatcher authorizes -> current holder returns, or recovered return offer is accepted and actual pickup confirmed -> Rider records handoff -> distinct authorized Staff records physical receipt -> exact items/quantity/condition -> supported existing stock/source handling -> physical completion. Financial/source obligations remain actionable. Already-shop parcels reuse recorded receiver evidence without another trip. Unsupported quantities/unsafe outcomes stay owned and actionable.
- **Historical final loss later recovered:** append genuine investigation without assigning custody; reporting Rider reports recovery against original incident -> normal Dispatcher return review/offer/pickup/receipt. Never invent prior confirmation, receiver or provider success.
